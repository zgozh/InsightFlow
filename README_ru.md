# InsightFlow

InsightFlow — контролируемая рабочая среда для бизнес-аналитики на базе агентного runtime DeerFlow v2.1.0-rc0. Репозиторий сохраняет upstream-лицензию MIT и уведомления об авторских правах. Условия описаны в [LICENSE](LICENSE), исходный проект — [DeerFlow](https://github.com/bytedance/deer-flow).

## Возможности

- Контролируемая аналитика зарегистрированных источников данных, метрик, отчётов и журнала аудита.
- Анализ в рамках диалогов, потоковые ответы, артефакты, обычные задачи субагентов и запуски по расписанию.
- Ограниченный веб-поиск: DuckDuckGo и получение страниц через Jina.
- Настраиваемые оператором MCP-серверы и навыки; устанавливаемые навыки проверяются SkillScan.
- Режимы песочницы Local и AIO для файловых инструментов и команд.

В интерфейсе есть анализ, чаты, источники данных, метрики, отчёты, история и задачи по расписанию. Удалённые IM-мосты, редактор Custom Agent, страницы проектов/документов/корзины и интерактивное управление браузером не входят в продукт.

## Быстрый старт

Требуются Docker Compose, Python 3.12+, Node.js 22+, uv и pnpm 10.26.2+.

1. Создайте локальную конфигурацию и установите зависимости:

   ~~~sh
   make config
   make install
   ~~~

2. Отредактируйте игнорируемый Git файл config.yaml и задайте хотя бы одну модель в models. Храните OPENAI_API_KEY, DEEPSEEK_API_KEY и другие секреты в переменных окружения.
3. Запустите среду разработки:

   ~~~sh
   make dev
   ~~~

Откройте http://localhost:2026. Опубликованный порт Nginx по умолчанию привязан к loopback-интерфейсу. Для оптимизированного локального запуска используйте make start, для Docker production — make up.

Не добавляйте в Git config.yaml, extensions_config.json, .env и ключи провайдеров. См. [настройку](backend/docs/CONFIGURATION.md) и [установку](Install.md).

## Границы Analytics и Agent

Запросы Analytics проходят через управляемый query-сервис: секреты источников остаются на сервере, планы авторизуются до исполнения, а история аудита сохраняется. Инструменты Agent не обходят этот сервис.

Lead Agent делегирует обычные задачи встроенным субагентам. Плановые запуски используют стандартный жизненный цикл Gateway. Команды в Local-песочнице выполняются с правами хоста Gateway; AIO использует отдельный сервис песочницы. Внешний AIO provisioner — это только настроенный адрес клиента: репозиторий не поставляет и не запускает такой сервис.

Считайте MCP-серверы, расширения, провайдеров моделей и адреса песочниц доверенными. Не открывайте Gateway напрямую в недоверенную сеть.

## Разработка

~~~sh
make check
cd backend
make test
make lint
cd ../frontend
pnpm check
pnpm test
pnpm test:e2e
~~~

Стандартный backend-набор работает офлайн; тесты с реальными провайдерами включаются отдельно. См. [backend guide](backend/AGENTS.md), [frontend guide](frontend/AGENTS.md) и [сценарии приёмки](docs/acceptance/acceptance-scenarios.md).
