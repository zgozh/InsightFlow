# ADR 0005：受控分析的耐久证据与固定内部角色

- 状态：已接受（主会话方案；各实施切片仍待独立验收）
- 日期：2026-10-07
- 依据：用户选择完成AS-01～AS-15；AS-14已批准的固定工具边界保持。

## 决策

分析Lead可见的模型工具schema与执行分发继续精确为目录、查询、报告三个工具。SQL Analyst、Data Analyst、Reviewer、Report Writer由App服务器固定内部调用，采用独立职责提示、受限输入、无通用工具的模型执行与有界失败策略；它们不是模型任意派生的task，也不能递归创建子Agent。Metric Service是读取受权已登记指标、解析分析口径的服务，不是新增模型工具或独立Agent。

查询继续经现有SQL Policy/语义授权/EXPLAIN/只读数据库执行，SQL Analyst不能直接连库。Data Analyst只能用该owner/thread/run准入的证据，不能访问其他数据源或文件。报告先经确定性数字引用检查与有界Reviewer，最后通过run-scoped writer输出；数学计算由确定性代码核算，模型只解释受限结果，不以“模型同意”替代数值一致性。

证据DTO与摘要计算属于domain纯标准库契约。`AnalysisRunEvidenceCollector`保持run内缓存功能，新增共享应用库的不可变成功查询证据仓储及固定JSON结果artifact能力，保存owner/thread/run/evidence关联、规范结果、版本和摘要。不保存SQL、plan token、secret或异常正文。结果数据在受控结果载体中持久化，不进入审计/事件/公开metadata；artifact正文仍沿用既有owner边界。

新增Analytics自己的`analytics_query_evidence`表，通过独立Alembic链追加迁移，不改历史revision、不向Harness ORM加入App表、不跨链外键。写入幂等且冲突不可覆盖；每run最多20份、结果快照合计16MiB，并用应用数据库事务串行化容量检查。重启后同身份可重新解析原run证据，后续checkpoint续跑通过服务器验证的来源run关系重建工作集；不能由客户端任意指定别人的run或证据。

## 实施顺序与检查

1. 领域共享证据DTO、仓储接口、SQLite/PG适配与增量迁移，证明不变量/身份/预算/不可覆盖/损坏拒绝/重开读取。
2. Gateway结果artifact能力、查询/报告bridge与恢复，证明query→artifact→耐久证据→同run发布/续跑的可信绑定。
3. 固定内部角色与结构化数字引用，证明实际独立执行、阶段顺序、串行查询、失败策略和数字/单位/期间/分母追溯。
4. 安全结构化阶段事件与前端投影，再真实双库模型、调度、应用PG恢复验收。

这是共享与持久化安全边界，按V2/V3直接受影响测试、真实迁移/恢复与最终集成验证；不为一处改动反复全仓测试。原五服务演示栈/四服务隔离栈数据不清理。公开产品文档在行为真正实现与验收后更新，不提前宣称角色链或发布完成。

## 不采用

- 在可信分析重开普通task、MCP、bash或任意文件工具：会扩大已批准权限。
- 只用角色标签或提示词扮演宣称多Agent：缺少独立执行证据。
- 在事件/审计/checkpoint直接塞结果行或原SQL：违背结构化输出边界。
- 扫描任意Markdown数字、发现曾在任意结果中出现就认定正确：不能证明分母、单位、期间或计算关系。
- 为恢复新增第二应用数据库/独立服务：现有共享应用库与线程目录足够。
